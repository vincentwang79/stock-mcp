# 数据采集、标准化、持久化与盘后发布

状态：local-ready-for-agent

## 问题

每日复盘必须来自一个完整、可追溯的价格源。上游延迟、缺列、日期错误或跨源拼接
都不能静默成为候选结论。

## 方案

建立 Tushare 日线主适配器、BaoStock 元数据/日历适配器和 AKShare 当日快照适配器，
统一为整数单位并保留来源时间；使用 SQLite 幂等保存；由单进程调度器在交易日
16:30 后重试并只发布通过验证的日报。

## 用户故事

- 每个发布日报只能使用一个完整价格源，并展示来源及时间。
- 非交易日应跳过，上游不完整应重试，18:00 后明确失败。
- 主源失败且备用源没有同源历史镜像时，应返回 `degraded_no_screen`（降级且不筛选），不得生成候选。
- 重启、重跑和备份不得产生重复日报或损坏数据。

## 实现决策

- Tushare `daily` 是正式主源；AKShare 默认只支持显式当日查询。
- 价格用万分之一元、成交量用股、成交额用分存储。
- SQLite 开启 WAL 和外键，日报幂等键包含交易日及流水线版本。
- 本地在线备份在成功发布后执行并校验完整性。
- v3 在完成固定日期范围的日线回填后，必须显式运行 `python.exe -m stock_mcp.cli build-v3-facts`（Windows 运行目录中的 `current` 是目录联接，禁止依赖生成的 `stock-mcp.exe` 启动器）。该命令只读取本机 SQLite 中已记录的同源日线和随 Windows 发布包提供的行业 JSON，生成涨跌停与快照特征；不得联网、不得回写原始日线或市场快照。
- v3 事实写入是幂等且不可变的：相同事实可重复运行，已有事实与新计算不一致时必须失败，不能以覆盖旧值“修复”数据。行业缺失必须记录为 `unavailable`，不得把多个缺失行业归为虚构的同一行业。

## 测试决策

- 录制的标准化夹具，不访问实时接口。
- 覆盖单位、缺列、日期、OHLC、混源、重跑、失败和恢复。
- 从同一快照和策略版本重复生成的日报必须完全相同。
- 使用固定、脱敏、带来源时间的 SQLite 与行业 JSON 夹具验证 `build-v3-facts` 的离线性、幂等性、不可变冲突和行业缺失；标准测试不访问实时行情。

## 非目标

分钟线、tick、付费因子、跨源字段拼接、默认启用云备份。
