# 数据采集、标准化、持久化与盘后发布

状态：local-ready-for-agent

## Problem

每日复盘必须来自一个完整、可追溯的价格源。上游延迟、缺列、日期错误或跨源拼接
都不能静默成为候选结论。

## Solution

建立 Tushare 日线主适配器、BaoStock 元数据/日历适配器和 AKShare 当日快照适配器，
统一为整数单位并保留来源时间；使用 SQLite 幂等保存；由单进程调度器在交易日
16:30 后重试并只发布通过验证的日报。

## User Stories

- 每个发布日报只能使用一个完整价格源，并展示来源及时间。
- 非交易日应跳过，上游不完整应重试，18:00 后明确失败。
- 主源失败且备用源没有同源历史镜像时，应返回 `degraded_no_screen`，不得筛选。
- 重启、重跑和备份不得产生重复日报或损坏数据。

## Implementation Decisions

- Tushare `daily` 是正式主源；AKShare 默认只支持显式当日查询。
- 价格用万分之一元、成交量用股、成交额用分存储。
- SQLite 开启 WAL 和外键，日报幂等键包含交易日及流水线版本。
- 本地在线备份在成功发布后执行并校验完整性。

## Testing Decisions

- 录制的标准化夹具，不访问实时接口。
- 覆盖单位、缺列、日期、OHLC、混源、重跑、失败和恢复。
- 从同一快照和策略版本重复生成的日报必须完全相同。

## Out of Scope

分钟线、tick、付费因子、跨源字段拼接、默认启用云备份。
