# 数据采集、标准化、持久化与盘后发布

状态：local-ready-for-agent

## 问题

每日复盘必须来自一个完整、可追溯的价格源。上游延迟、缺列、日期错误或跨源拼接
都不能静默成为候选结论。

## 方案

建立 Tushare 日线主适配器、BaoStock 元数据/日历适配器和 AKShare 当日快照适配器，
统一为整数单位并保留来源时间；使用 SQLite 幂等保存；由单进程调度器在交易日
16:30 后重试并只发布通过验证的日报。

## 用户故事

- 每个发布日报只能使用一个完整价格源，并展示来源及时间。
- 非交易日应跳过，上游不完整应重试，18:00 后明确失败。
- 主源失败且备用源没有同源历史镜像时，应返回 `degraded_no_screen`（降级且不筛选），不得生成候选。
- 重启、重跑和备份不得产生重复日报或损坏数据。

## 实现决策

- Tushare `daily` 是正式主源；AKShare 默认只支持显式当日查询。
- 价格用万分之一元、成交量用股、成交额用分存储。
- SQLite 开启 WAL 和外键，日报幂等键包含交易日及流水线版本。
- 本地在线备份在成功发布后执行并校验完整性。
- v3 在完成固定日期范围的日线回填后，必须显式运行 `python.exe -m stock_mcp.cli build-v3-facts`（Windows 运行目录中的 `current` 是目录联接，禁止依赖生成的 `stock-mcp.exe` 启动器）。该命令只读取本机 SQLite 中已记录的同源日线和随 Windows 发布包提供的行业 JSON，生成涨跌停与快照特征；不得联网、不得回写原始日线或市场快照。
- v3 事实写入是幂等且不可变的：相同事实可重复运行，已有事实与新计算不一致时必须失败，不能以覆盖旧值“修复”数据。行业缺失必须记录为 `unavailable`，不得把多个缺失行业归为虚构的同一行业。
- v3 实时日报使用 BaoStock 当日可见交易日历固定前 60 个市场会话。单只证券缺少其中某日价格时，只有本地不可变 BaoStock 事实明确记录该证券当日 `tradeStatus=0`，才允许把该证券单独排除；`tradeStatus=1` 或状态证据缺失必须使该次发布失败并保留重试能力，不能用更早价格替代，也不能把真实数据缺口伪装为停牌。
- 实时 v3 行业解释、涨跌停事实、原始 Tushare 快照、观察/日报和流水线状态在同一 SQLite 事务内发布。新上市、合法停牌或单证券历史不足不得阻断其他完整证券；防御市场或无形态时仍可合法产生零候选日报。

## 测试决策

- 录制的标准化夹具，不访问实时接口。
- 覆盖单位、缺列、日期、OHLC、混源、重跑、失败和恢复。
- 从同一快照和策略版本重复生成的日报必须完全相同。
- 使用固定、脱敏、带来源时间的 SQLite 与行业 JSON 夹具验证 `build-v3-facts` 的离线性、幂等性、不可变冲突和行业缺失；标准测试不访问实时行情。

## 非目标

分钟线、tick、付费因子、跨源字段拼接、默认启用云备份。

## Schema v11 与新浪可选链路

- Tushare 继续是正式价格源；新浪股本、换手率和市值差异使用独立不可变事实表，不能塞入 `DailyBar`。
- 新浪历史、股本和 spot 使用纯 Python 严格解码、固定单位、注入式 HTTP、串行限速及可恢复 checkpoint。失败只留下抓取证据，不留下部分正式快照。
- 单证券历史、股本、成功抓取证据和 checkpoint 必须在同一个 SQLite 事务中发布；失败响应只追加失败 evidence。压缩 KLC 由纯 Python 位流解码器处理并受固定录制夹具保护；真实端点单位对照和 Windows 断点恢复仍是外部门禁。任何解码或完整性失败都必须显式失败，不能执行上游 JavaScript 或借用 Tushare 补洞。
- shadow 默认关闭。资格需要连续 20 个收盘交易日、完整分页/证券集合、BaoStock 状态覆盖、同源 60 日历史、差异和条款人工审阅以及 Windows 实机验证。
- 备用价格切换必须整份使用新浪 OHLC、前收、量额和同源历史；任一门禁不满足均返回 `degraded_no_screen` 和零候选。
- shadow 只能标记为当前已收盘交易日，必须保存每页抓取证据；任意历史或未来 `trade_date` 标签都必须拒绝。
